# Governance

NetPulse uses a maintainer-led model. The repository owner is responsible for technical direction, reviews, releases, security decisions, and access to project infrastructure.

## Decisions

Routine changes are decided through issue and pull-request review. A proposal is evaluated on correctness, diagnostic value, privacy impact, maintenance cost, compatibility with supported Macs, and fit with the project's scope.

Large changes should begin with an issue that describes the problem, alternatives, and migration cost. The maintainer records the decision in that issue so future contributors can understand the context.

## Contributions

Anyone may open an issue or pull request. Acceptance does not depend on prior contribution history. The maintainer may request changes, narrow the scope, or decline work that adds ongoing complexity without enough user value.

## Releases

Releases follow semantic versioning. Beta releases may change behavior and data presentation before the stable `1.0.0` release. Tags and published assets are treated as immutable; corrections are shipped in a new release.

## Changes to governance

Governance changes are reviewed in public through a pull request. Security reports and conduct reports remain private until disclosure is appropriate.
